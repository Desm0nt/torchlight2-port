# Torchlight II (Switch) → нативный Android: состояние и журнал

Подход тот же, что у DOOM 2016 / Eternal / XC2 / Diablo III: ARM64-код игры исполняется напрямую, NSO патчится офлайн
(x18/TLS/SVC/cntpct), `nn::` — HLE, NVN → Vulkan, шейдеры офлайн. Дерево — клон публичного D3-репо (`d3-port-repo`, main 0545886),
ветка `tl2`; сборка `DM_GAME=tl2` = ядро DOOM + `DM_GAME_D3` (общий SDK 8.2 / NVN 53) + `DM_GAME_TL2` (выключает D3-специфичное).

## Вход
| Файл | Что |
|---|---|
| `Torchlight 2\Torchlight II [010090400D366000][v0].nsp` (1.7 ГБ) | база |
| `...[010090400D366800][v327680].nsp` (0.5 ГБ) | апдейт v5 (BKTR) |
| `DLC\Torchlight II [DLC Yapper][010090400D367001][v0].nsp` | питомец (AOC 1), пока не подключён |

## Разведка (06.11.2026)
- Движок **Ogre 1.x + FMOD Ex**, порт Panic Button (как DOOM 2016 Switch). Видео — `PanicMoviePlayer` через `nn::movie` (MP4/H.264).
- Модули: `main` (build-id a0c6c2d2…), `sdk` **3ae34e68… = тот же SDK 8.2.0, что у D3**, `subsdk0` = NintendoSDK movie (Android Stagefright).
- main: 846 импортов, `nvnBootstrapLoader` единственный NVN-импорт (остальное через GetProcAddress), набор имён NVN = D3.
- npdm: prio 44, core 0, **SystemResourceSize 0** (без VAMM, как DOOM 2016), стек 1 МиБ. ProgramId 010090400D366000.
- RomFS (база + BKTR, IVFC ок): 257 файлов, 1.88 ГиБ: `PAKS/DATA*.PAK(+.MAN)`, `PROGRAMS/*.NVN` (шейдеры), `MOVIES/*.MP4`,
  `MUSIC`, `CONSOLELOC/<LANG>.LANGUAGE` (de en es fr it ja pl pt_br ru zh_cn zh_tw — все языки в RomFS), `SPLASH.XTX`.
  Пути в коде — `ROM:/PROGRAMS/…` (верхний регистр, как в RomFS).
- Глубина: сразу после инициализации устройства `nvnDeviceSetWindowOriginMode(1)` + `nvnDeviceSetDepthMode(1 = NEAR_IS_ZERO)`
  безусловно (main 0x199e4f8 / 0x199e50c; указатели процедур main+0x7702940 / +0x7702948) — как D3.

## Патч NSO
`DM_TARGET=android python src/dm/tools/patch_nso.py work/exefs-update/<mod> work/patched <mod>` для main, sdk, subsdk0;
`equiv.py`: **0 расхождений**, мутации 300/300 на всех трёх (main 6 550 мест, sdk 11 277 / 93 гейта, subsdk0 10 639).
- Новый вид таблицы переходов (main 0x19e0a6c): `adrp x18 + add x18; mov x0,x18; ldrsw x18,[x18,x13,lsl #2]; add x18,x18,x0; br x18`
  — загрузка по оригиналу базы, а `add` по копии. `jump_offsets` теперь принимает это, только если инструкция прямо перед загрузкой —
  `mov rb,<база загрузки>` (раньше на таких местах был assert, так что остальные сайты не меняются).

## Шейдеры
Каждый `PROGRAMS/*.NVN` (и `skin*_c.nvn`) — одна стадия, голый GLSLCoutput (магия 0x19866891, как `.sb` DOOM 2016 без 8-байтной
обёртки id): секции 0 GPU code, 1 asm, 2 perf, 3 reflection, 4 hash. `tools/tl2_shader_jobs.py` → `work/shaders-jobs` (формат
d3_shader_jobs.py, ключ nxnative control+code), пары vs/ps по именам из `CONSOLE_SHADERS.PROGRAM`, факт `depth_zero` для всех vs.
64 стадии (28 vs, 32 ps, 4 cs-скиннинг), 36 программ, 0 проблем. Перевод `dmsh_vk_xc2.py` (транслятор D3): **64/64 ok**, 4.98 МБ.
```
python src/tools/tl2_shader_jobs.py work/romfs/PROGRAMS work/shaders-jobs
XLATE=…/dmsh_xlate.exe SPIRV_OPT=… SPIRV_VAL=… J=12 python src/dm/gfx/tools/dmsh_vk_xc2.py work/shaders-jobs work/shaders-vk
```

## Широкий экран (DM_TL2_WIDE, по умолчанию вкл., 07.11.2026; на телефоне ещё не проверено)
Размер TL2 у системы не спрашивает: константы рядом с `oe::GetOperationMode` (main = `main.raw`, build a0c6c2d2):
| Где | Что |
|---|---|
| `0x199417c orr w27,#1920` / `0x199418c mov w27,#1280` (+ `mov w8,#1080/#720`) | окно NVN: 3 swap-текстуры (SetSize2D `0x1994430`), размер render window `+0x24/+0x28` (`0x1994954`), цель `0x1991260`; перестраивается по флагу `+0x5f4` |
| `0x7264b4 orr w8,#1920` / `0x7264cc mov w20,#1280` | init игры: ПК-настройки WIDTH/HEIGHT (id `0x753f4c4/c8`, дефолт 800x600 в `0x270ad0`) |
| `0x1317b8 orr w2,#1920` / `0x131720 mov w21,#1280` | то же по сообщению о смене режима (цикл TryPopNotificationMessage) |
| `0x72cce0` CreateViewports | аспект камер = actual width / height вьюпорта → `setAspectRatio`, FOV вертикальный ⇒ шире окно = **Hor+** |
| `0x72e330` → `0x275a90` | применение видеонастроек: снап WIDTH/HEIGHT к ближайшему режиму из списка, затем аспект камер из них — снап сделан тождеством |
| `0x140f28 orr w3,#1920` → `0x19fef80` | холст консольного UI (CConsoleUI*, «UI_CONSOLE») 1920x1080 в обоих режимах (масштабируется на окно); полноэкранные панели — литерал (1920,1080) `0x1f71810`/`0x1f69298` |

`dm/host/hle_tl2_wide.c` (`dm_tl2_wide_install`, из `main.c` после `load_modules`): сверка 6 окон слов, затем окно/настройки = W x 1080
(портатив W·2/3 x 720), W = 1080 × аспект экрана (кратно 16; 3200x1440 → 2400). Ручки: `DM_TL2_WIDE=0` (как на Switch) / `=<ширина>`.
Java: шестерёнка «Формат картинки», для TL2 по умолчанию «широкий» → `DM_TL2_WIDE=<W>|0`.

**UI в широком режиме — гибрид (по умолчанию, `DM_TL2_WIDE_UI` не задан / `2`)**: холст W x 1080 (`0x140f28` → W); HUD на всю ширину
(привязан к краям, не растянут), всё остальное — в центральной полосе 1920. Устройство PUI: менеджер UI (`main+0x74cfe70`) в настройке
`0x141020` вешает на корень PUI слой экранов `+0xa0` (каждый CConsoleUI в своём Show, слот 6, делает `слой->AddChild(свой корень)` +
`Relayout`), загрузку `+0x90`, модальный диалог `+0x50`, тосты приглашений `+0xf8/+0x100`. Хуки (`hle_tl2_wide.c`, всё сверено слово
в слово): AddChild `0x19f59a0` / `0x19f59e0` переписаны в C (тот же список) и для детей слоя запоминают адрес возврата вызова; Layout
`0x19f5a90` входит через `ui_layout`: ребёнок слоя, вызванный не из HUD-места, а также загрузка и диалог раскладываются в прямоугольнике
`[(W−1920)/2, +1920]` родителя (поддерево следует), остальное — как было (пролог в отдельной странице + переход на `0x19f5aa0`).
HUD-места (адреса возврата): Hud Show `0x125cfc`, Hud Create `0x124a24/0x124a9c/0x124b30/0x124bec`, LocalPlayerHud `0x12013c`,
MultiPlayerHud `0x1227ec`, TextEventsHud `0xbc77c`, TargetEnemyHud `0xbded4`, StoryHud `0xbed1c`, Loot (подписи предметов)
`0x1193ac`, CConsoleAutomap `0x129ce0/0x129da0/0x129e3c/0x12bfec/0x12c010/0x12c034/0x12c44c`; `DM_TL2_WIDE_KEEP=<hex>,...` — добавить
(лог: `[wide] UI screen ... added by main+XXXX: HUD | centred 1920 band` для каждого нового ребёнка слоя). Единицы холста = широкий холст,
поэтому тапы и вырезка иконок (`dm_tl2_ui_canvas_to_frame`, карта 1,1,0,0) верны без поправок. `DM_TL2_WIDE_UI=1` — только широкий холст
(эксперимент), `=0` — холст 1920, растянутый на окно. Сплэш при старте (DrawTexture 16:9 на всё окно) — в центральную полосу, по бокам
чёрное (`xbg_game.cpp` `draw_texture`, `dm_tl2_splash_band`).
**Внутриигровые меню в полосе (09.11.2026, статика; на телефоне ещё не проверено).** Инвентарь / персонаж / навыки / квесты /
питомец / торговцы — не дети слоя экранов: это `CConsoleUIRadialMenu` (vt 0x230d6d8, панели `Panel` живут внутри), его Show
(слот 6 = `0x137760`) вешает свой корень (`+0x50`, простой PUI::Element из Create `0x134ec0`, якоря 0..1) прямо на корень PUI
(`main+0x927a970 +0x308`, AddChild vt+0x58, адрес возврата `0x13778c`) — поэтому строки «added by» не было, корень раскладывался на
всю ширину и дети (якорь 0 + смещения под 1920) прилипали к левому краю. Теперь дети корня PUI из «полосных» мест (`0x13778c`;
`DM_TL2_WIDE_BAND=<hex>,...` добавляет) раскладываются в полосе `[(W−1920)/2, +1920]`, прочие дети корня (слой, тосты, элементы
игроков `+0x198`) — как были. Колесо (`PUI::Radial`, vt 0x2365628) ставит центры сегментов (`+0xa8..` по 0x118, `+0x4c`) только из
своих смещений, без прямоугольника: его Layout `0x19fd5e0` и SetSegments `0x19fd7a0` входят через обёртки, которые после оригинала
прибавляют к x центров сдвиги полосы предков. Тапы: hle_tl2_ui.c бьёт по разложенным прямоугольникам и этим центрам — всё
следует само. Лог: `[wide] UI panel root … added to the PUI root by main+0x13778c (CConsoleUIRadialMenu Show…): centred 1920 band`,
`[wide] centred 1920 band: radial menu … (type T, tab N), <панель> (vt main+…), root … at x 240..2160 of canvas 0..2400`,
`[wide] radial wheel … (Layout|SetSegments): K segment centres moved +240 with the centred band`; новые дети корня из других мест —
`[wide] PUI root child … added by main+XXXX: whole width (DM_TL2_WIDE_BAND=XXXX would centre it)`.

**Экраны загрузки — 16:9 с чёрными полосами** (по умолчанию; `DM_TL2_WIDE_LOADSTRETCH=1` / шестерёнка «растягивать экраны загрузки» —
растянуть). Экран загрузки — узел консольного UI `CConsoleUILoading` (vtable `0x2304530`, создаётся `0xc1e40` из `0x141020`, указатель в
менеджере UI `+0x90`; менеджер — статик `main+0x74cfe70`, GOT `0x23a3590`). Байт узла `+0x74` = рисуется (базовый Render `0x19f57b0`
без него выходит), `+0x75` = обновляется: Show `0xc2a30` ставит оба (`0xc2ae4 strh #0x101`), Update `0xc30f0` гасит по концу
затухания (`0xc3168`); игра сама проверяет его в `0x112718`. Пока `+0x74` ≠ 0, презентер (`vulkan_present.cpp`, хук
`dm_present_pillarbox`, поток трансляции): в гибриде — только центральную полосу 16:9 окна (там уже лежит арт загрузки), по бокам
чёрное; с LOADSTRETCH — эту полосу на весь экран; при `DM_TL2_WIDE_UI=0` — всё окно сжато в 16:9. С `DM_TL2_WIDE_UI=1` не включается.
Тач: игра читает панель только раз при старте (`0x13ea04`), менять нечего. В nxnative/nx2android общего механизма нет (у них
пер-игровые патчи `DM_SCREEN_ASPECT`).

## Сборка и запуск
```
cmake -S dm/android -B work/build-android -G Ninja -DCMAKE_TOOLCHAIN_FILE=<ndk>/build/cmake/android.toolchain.cmake \
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-31 -DCMAKE_BUILD_TYPE=Release -DDM_GAME=tl2
GRADLE=<gradle.bat> powershell -File tools/build_apk.ps1            # -> work/TL2-port-debug.apk (org.torchlight2.port)
bash tools/push_phone.sh                                             # dm/out, dm/shaders, turnip27, APK, RomFS -> Download/Torchlight2Mobile
bash tools/run.sh <имя> [сек] [ENV=…]                                # лог work/logs/<имя>.log, игра закрывается после
```
Данные на телефоне: `/sdcard/Download/Torchlight2Mobile/{romfs, dm/out, dm/shaders, dm/env, drivers, logs}`.

## Первые запуски (07.11.2026, Mi 14 Ultra, Turnip 27)
- r2: первый кадр рисуется `nvnCommandBufferDrawTexture` (у нас не было) → «present a texture never rendered». Сделано: запись
  `OP_X_DRAW_TEX` (hle_nvn.c) и `draw_texture` в xbg_game.cpp — хэндл из текущего пула, blit с фильтрацией и конвертацией формата
  в colour target 0 (`draw_tex_blit` разрешает разные форматы). Блендинг и отражение регионов не учитываются (сплэш/меню непрозрачные).
- r4: `nn::fs::IsSaveDataExisting(ApplicationId, Uid)` (main+0x1335e4) шёл в нативный fsp-srv — хук был только в hle_xc2.c.
  Перенесены в hle_tl2.c: этот хук, `MountSaveDataReadOnly`, `ec::ShowShopApplicationInformation`, плюс по сверке импортов TL2 с
  nxnative/nx2android (MIT): ldn после Initialize, `nifm::GetCurrentIpConfigInfo`, `socket::GAIStrError` / `SendTo(MsgFlag)` /
  `Shutdown(ShutdownMethod)`, геттеры AudioIn, `account::AsyncContext::operator=`. os/util/mem/crypto из сверки не нужны: это код
  SDK без сервисов, их не перехватывают и nxnative/nx2android. Сверка «по именам» должна учитывать все строки `"_Z…"` (макросы
  SKF/SKD/SSF в hle_net.c) и гейты (хуки из hle_xc2.c в сборку tl2 не входят; `oe::Enter/LeaveExitRequestHandlingSection` — в hle_d3.c).
- r6–r7: меню и создание персонажа, 60 fps (gpu ~12 мс, submit ~6 мс).
- Скиннинг: TL2 скинит на GPU compute-шейдерами `skin1..4_c` (палитра костей — UBO 0 = c3, 64 байта на кость, `nVerts` в c3+0x4000;
  s0 вход, s1 веса, s2 выход). Симптом: у всех персонажей, NPC и монстров нет анимаций, bind-поза, шипы из рук и рогов. Игра
  анимирует нормально (хэш палитры меняется каждый бинд). Причина: `tl2_shader_jobs.py` не писал факты compute `local` / `shared`
  (control +0x748 / +0x754), транслятор объявлял LocalSize 1,1,1, а шейдер считает индекс как CTAID.X * 64 + TID.X — скинилась
  одна вершина из 64. Исправлено в tl2_shader_jobs.py (как xc2_shader_jobs.py), перевод заново: изменились только 4 cs.
- Отладка по Wi-Fi adb: `work/bin/radb` (adb с переподключением, RADB_HOST=ip:port; ADB=…/radb для run.sh / shots.sh) и
  `work/bin/shot` (скриншот, бинарно-безопасный). run.sh в конце закрывает игру — не запускать, пока на телефоне играют.

## Тач (07.11.2026)
**Статика: у Switch-TL2 тача нет.** `nn::hid::GetTouchScreenState<16>` вызывается ровно один раз — в init hid (main 0x13e9d0:
InitializeNpad → InitializeTouchScreen → SetSupportedNpadStyleSet(7) → SetSupportedNpadIdType → `GetTouchScreenState(this+0x278)` 0x13ea04),
опрос пада (0x13ea60, GetNpadStyleSet / GetNpadState ×3 стиля) тач не читает; других вызовов (bl / b на PLT 0x1df97c0) нет. Мыши/клавиатуры в
импортах нет. CEGUI 0.6.2 внутри, но имена событий мыши вырезаны (нет строк `MouseClick` / `MouseButtonDown` / `Clicked`), cvar
`input_forceGamepad` регистрируется (0x6b940c) и больше нигде не читается. Меню — консольные фокусные / радиальные
(`CConsoleUIMenu`, `CConsoleUIButtonMenu`, `CConsoleUIRadialMenu`, `CConsoleUIMainMenu`, `CConsoleUIStartMenu`, `CMenuController`).
Итого тач в игру слать некуда (hle_tl2.c отдаёт touch_fill честно, но читается он один раз при старте); весь тач — во фронтенде → npad.
Тап по конкретному пункту меню — см. «Тап по пунктам меню» ниже (DM_TL2_POINTER, за гейтом).

**Раскладка `tl2` (по D2R Mobile, `Tl2Touch.java`; D3PadView только передаёт ей касания/рисование, по умолчанию для TL2):** плавающий стик
(левые 40% × нижние 55%, от точки касания, 60 dp полный ход, 6 dp мёртвая зона, поправка диагонали `tl2_iso`), веер справа как у D2R
(A основной, B X Y R, ZR на месте портала, II = второй набор: модификатор `tl2_mod` за 170 мс до навыка), перетаскивание навыка = прицел
(`tl2_aim` правый / левый стик / выкл), короткий тап = импульс с направлением, увод пальца на «−» = отмена; нижний ряд D2R-«пояса» = ←↑↓→ +,
сверху ZL L L3 / − R3 / ⚙ / МЕНЮ. Мир: тап = `tl2_tap` (выкл / A / повернуться+A), держать = идти к пальцу (`tl2_hold_walk`, якорь героя
`tl2_hero_y`). Режим меню (как панельный режим D2R): тап = A, долгое = держать A, два пальца = B, свайп = шаги крестовины (`tl2_nav_swipe` 0)
или левый стик (1, радиальные меню); игра стартует в нём, + / − включают его сами (`tl2_auto_nav`). Иконки навыков D3 (D3SkillIcons) для TL2 выключены.

**Пересмотр после проверки владельцем (07.11.2026):** режима меню больше нет (тап = A / свайп = крестовина / два пальца = B / МЕНЮ-ИГРА /
авто по + −) — убран из кода и ⚙ до настоящего тача по пунктам (мышиные события CEGUI, отдельная ветка). По умолчанию (`tl2`): два

максимум; EnsureVisible `0x1a024b0` (хвост SetSelected) докручивает до выбранной строки; SetRowHeight `0x1a02150` (и SetCount `0x1a023a0`)
зажимают `+0x10c` в 0..max и ставят ползунок. Стрелки — элементы списка `+0x118`/`+0x128` (вверх, scroll > 0) и `+0x120`/`+0x130` (вниз,
scroll < max и есть выбор), Draw `0x1a01bc0..0x1a01d98` включает им `+0x74` каждый кадр. На Switch это только индикатор: листает стик (выбор
+ EnsureVisible).
- Тап по стрелке (rect элемента ±36 ед. канваса, строка под пальцем важнее) = страница (видимых строк) вниз / вверх.
- Вертикальный свайп над прокручиваемым списком: Tl2Touch, палец `T_MENU` сдвинулся (> MOVE_DP), |dy| > |dx| и `nativeTl2UiListHit(x0, y0)`
  (поток ввода публикует области строк списков с max > 0, раз в 4 опроса) → `T_DRAG`: `nativeTl2UiDrag(x0, y0, dy, 0/1/2)`; строки идут за
  пальцем шагами по высоте строки (палец вверх = дальше по списку), отпускание тапа не даёт. Горизонтальные движения и тапы — как было.
- Механизм: `+0x10c` += rows × rowh, затем собственный SetRowHeight списка (зажим + ползунок). Если выбранная строка ушла из видимых, выбор
  переносится на ближнюю видимую способом владельца (список панели радиала — фокус панели, как тап, со звуком; список верхнего меню —
  SetSelected), чтобы следующий EnsureVisible игры не откатил прокрутку. В превью панели (state ≠ 1) выбор не трогается.
- Лог: `[tl2ui] tap … on the down scroll arrow of list …`, `[tl2ui] scroll (arrow|drag|request) list … +N rows: scroll A -> B (max M, …),
  selected S -> T (…)`, `[tl2ui] drag start at UI … on list …` / `drag end: +N rows`, `… already at the end`; если игра потом вернула
  прокрутку — `[tl2ui] scroll: list … scroll is X 20 polls later (was set to Y): reset by the game`. Дамп `dm/tl2-ui-dump.tsv`: у списков
  `max` и `arrow+0x118 … drawn`.
- Тест без пальца: файл `dm/ui-scroll-now` «x y rows» (доли картинки, rows + = дальше). Гейт тот же `DM_TL2_POINTER`.

**Задания: свои списки панелей и текст (09.11.2026, после теста на телефоне; собрано, не проверено).** Лог хозяина: тап по квесту →
`list … row N is not held by the top menu RadialMenu: nothing`. Причина: PanelQuests (тип 12, ctor `0x64fd0`, vt `0x2303240`, HandleInput
`0x65e50`) в режиме `+0xe0 = 0` держит **свой** список квестов `+0x20` (не списки радиала `+0x240/+0x270`) и двигает его сам: Up/Down →

  выключенные/удалённые — стираются вместе с недописанными `.tmp`. Диалог прогресса только если есть что конвертировать. Хоть один пак →

  Switch (каталоги, затем файлы, по имени — RomFS-таблицы этой игры отсортированы, `work/romfs-list.tsv`), `DM_TL2_ROM_ORDER=0` в dm/env —

`tools/tl2_mod.py rawsim <romfs> <mod…> [--out d] [-v]` повторяет слияние игры (паки DATA..DATA5, затем моды в порядке ZMOD_00..): с nude +
werewolf + cacklespit итог 7698 юнитов (6210 / 1156 / 19 / 313), из модов в индекс попали 30/30, 6/6, 9/9, ни одного дубля GUID и ни одного
юнита без DAT; SKILLS 1660 + 9 + 12, AFFIXES +62, MISSILES +1 +1, TRIGGERABLES +1 — коллизий нет. Дубли внутри базы (DATA1..5 повторяют
зелья/петов/порталы) совпадают с DATA поле в поле, порядок для них неважен. Общий файл у nude и werewolf — только `UNITDATA.RAW`, так что
на уровне данных эти моды не мешают друг другу; причину «нет эффекта» искать не в индексах. Проверить на телефоне: в boot.log оба
`[tl2 mods] pack ZMOD_…` и оба «Loading Pack»; `DM_FSLOG` — из какого пака читается `MEDIA/WARDROBE/HUMAN/HUF_FACE_BER01.PNG`; эффект nude
виден только на человеке-женщине (у персонажа-оборотня гардероба нет).

Где моды реально конфликтуют (и как это решается):
- **Один и тот же файл** (DAT юнита/навыка, `WARDROBE/WARDROBESETS.DAT`, `UNITS/PLAYERS/*.DAT`, `UNITTYPES/*.DAT`, `GLOBALS.DAT`,
  LAYOUT, MESH, текстуры): файл заменяется целиком, слияния полей нет ни здесь, ни в GUTS на PC — работает версия пака, который
  выигрывает путь (эмулируется порядок Switch: DATA..DATA5, затем ZMOD_00.. по списку ⚙; «ниже в списке = перекрывает»). Два мода,
  правящие один DAT, совместимы только через патч-мод, объединяющий правки.
- **Один GUID в RAW у двух паков** (мод переопределяет юнит/навык базы новым DAT под старым GUID): побеждает первый загруженный —
  база; мод должен заменять DAT по тому же пути, а не регистрировать новый путь под старым GUID. `rawsim` показывает такие строки как `dup of`.
- **Удаления** (`deletes` в заголовке .MOD) → нулевые записи в паке, как DATA3 «удаляет» файл DATA.
- **Сохранения:** GUID предметов/классов модов пишутся в персонажа — поэтому отдельная папка `<save>-mods` (`DM_TL2_MODS_SAVE`).
- **UI PC-модов** (`UI.RAW`, `MEDIA/UI/MENUS/*`) консольный UI не использует.

изменившихся слотов (или раз в 5 с; не во время перезарядки) из кадра в host-буфер своим же командным буфером (vkCmdCopyImageToBuffer,
до blit; чтение после забора этого кадра — без лишних ожиданий), не чаще 4 раз/с; hle_tl2_icons.c сжимает в 64×64 ARGB и публикует со

кнопки A B X Y R ZR L ZL (веер, ячейки tl2_side, «мод+» ячейки — та же иконка) рисуют иконку в круге, буква — маленьким значком; пусто
(ничего не назначено) — буква тусклая. Второй набор (II): игра показывает в HUD свой набор — снимок следует за тем, что на экране.
Выключение: `DM_TL2_ICONS=0` в dm/env или prefs `tl2_icons=false` (галочки ⚙ пока нет — DmActivity правит другой агент).

**Правка 08.11.2026 (отзыв владельца).** Раскладка `tl2`: все 8 слотов HUD в веере вокруг A — внутренняя дуга 88 dp B X Y R (200°/155°/110°/70°),
внешняя 150 dp ZL L ZR (190°/158°/126°), II на 95° внешней; L / ZL / L3 убраны из верхнего ряда (L3 — к R3 справа сверху). `tl2_side`: у L / ZL
слева добавлены ячейки «мод+L / мод+ZL». Иконки: заполнение `+0x134` маски перезарядки читалось наоборот — 0 = готов (снимаем), между —
перезарядка (ждём), 1 = закрыт целиком / нельзя сейчас (снимаем через 2 с, если лучшего не было, — иконка тусклая, но верная); снимок только

fx = ox + sx·cx/cw, fy = oy + sy·cy/ch; по умолчанию 1, 1, 0, 0).

## Карта: мини-карта / большая карта (DM_TL2_MAP, по умолчанию вкл., 09.11.2026; на телефоне ещё не проверено)
**Как на Switch (статика, main v5):** полноэкранной карты нет, есть три режима автокарты, их листает **крестовина вправо** (код 5 = DPAD_RIGHT
по таблице глифов 0x230d8b0; в таблице подсказок 0x230d968 — `TOGGLE_MAP`): HandleInput менеджера UI 0x143800 при пустом стеке меню и HUD,
не взявшем событие, делает `mode = (mode + 1) % 3; on = mode > 0` (0x143978..0x1439e4, сеттер 0x1a0f30 объекта настроек 0x26caa0, id
`*main+0x753f60c` / `*main+0x753f610`). 1 = мини-карта (рамка `ig_automap` +0xd0, 230×230 единиц холста, справа сверху), **2 = большая
карта** (`map_background` +0xd8 и карта 400×670, ветка 0x12c088 SetVisible 0x12bf80; `+0x139` = 1), 0 = скрыта. Применяет сама автокарта в
своём update 0x12dc90 (сравнивает с прошлым значением). Крестовина вверх / вниз (коды 6 / 7) — масштаб (0x143c20, `+0xf0` 10..70).
`CConsoleAutomap` (vt 0x230a628, ctor 0x129630) живёт в уровне `+0x3a8` (0x3e6394); уровень игрока = 0x6c9fe0(client), client = `*main+0x75d49b0`.
В радиальном меню / паузе карты мира нет (панель 0x20 MapSelector — порталы карт-предметов).
**Сделано** (`dm/host/hle_tl2_map.c`): тап по показанной карте = мини ↔ большая — те же две записи настроек, что делает код крестовины, но 1 ↔ 2
(тап не прячет карту); только на потоке ввода игры (`dm_tl2_ui_pump`) и при пустом стеке меню. Зона тапа — прямоугольник нарисованного
элемента (+0xd8 / +0xd0, иначе контейнер +0x328, `+0x60` в единицах холста, + 12 единиц) через `dm_tl2_ui_canvas_to_frame`, публикуется раз в
6 опросов, пока карта показана и нет меню / диалога / загрузки. JNI `DmActivity.nativeTl2MapHit(x, y)` / `nativeTl2ToggleMap()`;
`nativeTl2UiTap` без меню и по карте тоже переключает. Tl2Touch: `mapHit` + одно условие в `begin` — палец на карте ждёт как тап меню (T_MENU),
сдвинулся — обычный стик / мир. Проверка без фронта: файл `dm/map-now` («t» — переключить, «0/1/2» — этот режим). Лог: `[tl2map] on`,
`[tl2map] mini|big map shown: … rect … = picture …`, `[tl2map] tap … on the map: toggle queued`, `[tl2map] map mode 1 -> 2 (big map …)`.
Сверка слов 11 мест + GOT (vtable, id настроек); не та сборка → выкл. Возврат кнопкой «назад» не сделан (назад = меню фронта).

## Совместимость с Mali / PowerVR и общие фиксы фреймворка (09.11.2026, ветка `tl2-mali-compat`; собрано, на устройстве не проверено)
Своего Mali нет: проверено кодом, офлайн-тестами и по KB (`docs/port-kb` MALI/PVR/TEX/SYNC/APP/HLE, `port-common`).

**«Чёрный экран при живом HUD» как в D3 (0.2.2–0.2.4):** у TL2 весь набор D3 уже есть и включается на не-Adreno сам —
`DM_GFX_VTX_RETYPE` (1 не на Adreno, `vtx_retype_mode()`: `vendorID != 0x5143`), самотест d3-perf ключей (`DM_GFX_D3PERF=1`,
`xbg_selftest.cpp`), `DM_GFX_DEPTH_FEEDBACK=0` не на Adreno, GVAL `DM_GFX_PASS_VALUES` (+`PASS_PROF` от DmActivity), `DM_GFX_CRUMBS=0`,
`QUERY_WAIT`, фолбэки MALI-02. Набор `"DM_*"` строк TL2 — надмножество D3; `xbg_vertex_retype.h`, `xbg_vendor_policy.h`,
`xbg_selftest.cpp` = D3 байт в байт (без CRLF). Покрытие форматов TL2: все 28 вершинных шейдеров `work/shaders-vk` переписаны
`xbg_vertex_retype` во все uint и во все sint (56 модулей, 0 отказов) и прошли `spirv-val --target-env vulkan1.1` (84 модуля).
Текстуры TL2 — BC1/BC2/BC3 + RGBA8 (XTX): на Mali/PowerVR идут через GPU-декод BC (ниже), DrawTexture — RGBA8→RGBA8 blit.

**Перенесено (коммиты):**
- `d7669f1` port-common: `audioout-keeper` (HLE-17, TL2 зовёт `OpenAudioOut`), `thread-exit-hoststack` (HLE-06), строки `[pc]` для
  `lse-select` / `vma-guard` (уже как в D3). `pc_check`: всё in sync; `lse_audit`: 523 ARMv8.0-переходника.
- `94e90a3` PVR-04 `DM_GFX_ANISO_FALLBACK=1`: без `samplerAnisotropy` сэмплер без анизотропии / выше лимита — до лимита, вместо fatal
  `result=-5`; модель `DM_GFX_SIM_GPU=powervr` теперь с `noaniso`; `vendor_policy_test` проходит.
- `4016472` (+`1d0d8a4`) TEX-02: шейдер GPU-декодера BC из D16 (06.11: экстрактор битов без UB, BC6H-блок раз на блок; `spv.h` сверен с
  glslc) — у TL2 был шейдер 05.11, на котором драйвер давал BC6H mode 1 с нулевыми строками 1–3 (чёрные квадраты); `DM_GFX_BC_SELFTEST=1`
  (2048 эталонных блоков на устройстве при первой текстуре формата; расхождение → этот формат на CPU; `=2` только лог, `=0` выкл.),
  `DM_GFX_BC_BARRIER=full`. Лог: `NVN BC decode: self-test fmt=… bad=… -> gpu|cpu`. На Adreno (нативный BC) путь не исполняется.
- `6e35989` SYNC-10: непривязанный VB → нулевой буфер 64 КБ + лог вместо FATAL `Unbound vertex buffer`.
- `3a0cafd` APP-02 stall watch (`stall_android.c` из D16/ETR; `DM_STALL_WATCH_MS=2000`): отчёт `【红】[stall]` по потокам в boot.log.
- `ffd385a` PVR-05 (для порта без `dm-record`): все `vkCreateShaderModule` под замком `DM_GFX_PIPE_SERIAL` (`gpguard::ModuleLock`;
  берётся только при serial = PowerVR): компилятор PowerVR работает и в создании модуля, а прогрев строит пайплайны параллельно.
- `a047759` HLE-25 безопасный выход из меню: `nativeQuit` → `dm_hold_quit` ждёт фиксации и тишины сейва (`DM_QUIT_SAVE_QUIET_MS=750`,
  максимум `DM_QUIT_SAVE_WAIT_MS=6000`); `hle_hold.c` = файл ETR (frontend-common + `g_quit`).

**Уже было / неприменимо:** TEX-07 `CUBEMAP_ARRAY` — гейт «XC2 или D3» в `nvn_tex.c`, сборка tl2 определяет `DM_GAME_D3` (запись MATRIX
была неверной); HLE-09 vma-guard, APP-04 LSE, SYNC-12, MALI-06/07/08 — как D3; TEX-03/04 ASTC-оверлей и санитайзер — оверлея у TL2 нет

**Осталось:** APP-01 PadSurface — пад TL2 (D3PadView + Tl2Touch) рисуется на окне; нужен `PadSurface.Painter` + один замок на всё

## Локальная сетевая игра по LAN (Pia поверх nn::ldn) — 13.11.2026 (ветка `wt/mp`; собрано, на телефонах не проверено)

Проверка (два телефона в одной Wi-Fi): в меню мультиплеера TL2 — локальная игра: создать на A, найти и войти на B. Строки: `[ldn] initialized`,
`[ldn] host: network created … local id 010090400d366000`, на B `[ldn] scan: 1 network(s) answered`, `[ldn] station: connected`, на A
`[ldn] host: node 1 joined`, затем `[net] lan: to <ip>:<порт> allowed` (UDP Pia) и `[net] lan: bind …`. Миграция хоста —
`[ldn] host: network created … (private: given session)` / private connect. Без локальной игры — ни одной такой строки.
